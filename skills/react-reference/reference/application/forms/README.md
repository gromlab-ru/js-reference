# Формы в React SPA

Для form state, validation lifecycle и состояния полей по умолчанию используется `@mantine/form`. Поля формы строятся на компонентах Mantine и следуют UI-правилам [`react-ui/README.md`](../react-ui/README.md).

## Разделение ответственности

| Ответственность | Владелец |
| --- | --- |
| Значения, touched, dirty и client validation | Form owner через `useForm` |
| Визуальное состояние и accessible error | Поле Mantine внутри form owner |
| Преобразование form values в предметный input | Владелец вызываемой domain operation |
| Бизнес-правила и доступность операции | Server и domain contract |
| Преобразование известных source errors | Domain adapter |
| Отображение ожидаемой ошибки submit | Form или ближайший action owner |

Форма является UI-состоянием пользовательского ввода. Не помещай её values в Zustand или SWR только ради submit. Если draft должен переживать unmount, reload или смену route, сначала определи отдельный смысл, владельца, lifecycle и правила конфликта с server state.

## Submit lifecycle

1. Проверь client-side ограничения, необходимые для корректного ввода.
2. Преобразуй values в предметный input на границе владельца операции.
3. Вызови operation через публичный фасет домена.
4. Не допускай повторный submit, пока текущая операция не завершена, если контракт не разрешает параллельные вызовы.
5. Отобрази известную ошибку рядом с действием или соответствующим полем.
6. Передай неожиданный сбой в общий механизм failure handling.
7. После успеха сбрось или сохрани форму согласно пользовательскому сценарию, а не автоматически.

## Validation

Client validation улучшает ввод, но не заменяет server validation. Не копируй на клиент изменяемые бизнес-ограничения, если сервер остаётся их единственным надёжным владельцем.

Field error должен иметь понятный текст и быть связан с полем через API Mantine. Summary или notification не заменяет field error, если пользователь должен исправить конкретное значение.

## Границы

- Не добавляй второй form state manager параллельно `@mantine/form` без задачи на миграцию.
- Не вызывай API client напрямую из submit handler для предметных данных.
- Не публикуй transport error или DTO в form component.
- Не очищай пользовательский ввод после неуспешного submit.
- Не используй schema library, persistence или autosave без отдельной задачи.
