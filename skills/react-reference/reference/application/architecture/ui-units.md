# UI-юниты в React

Применяй этот документ к самостоятельной публичной визуальной ответственности. Критерии юнита, слой, колокацию и направления зависимостей определяет skill `unit-architecture`; наличие React-компонента само по себе не создаёт юнит.

## Владелец

UI-юнит предоставляет универсальную визуальную возможность без предметного сценария: кнопку, диалог, layout primitive или другой элемент design system. Предметный UI принадлежит соответствующему домену, а route-level размещение готовых возможностей — `app` или composition owner.

Внутренний компонент остаётся implementation detail ближайшего владельца, пока у него нет самостоятельной ответственности, публичного контракта и внешних consumers. Не создавай фасет и каталог только ради сокращения JSX.

## Физическая форма

Самостоятельный публичный компонент с собственным DOM обычно имеет следующую форму:

```text
ui/button/
├── index.ts
├── button.tsx
├── styles/
│   └── button.module.css
└── types/
    └── button-props.type.ts
```

Это соглашение React-проектов, а не определение юнита. Упрощай форму, когда часть файлов не несёт роли. Provider, Guard или Error Boundary без собственного DOM не требует CSS Module, искусственного wrapper или пустого файла стилей.

## Публичный фасет

`index.ts` публикует только необходимый внешний контракт:

```ts
export { Button } from './button'
export type { ButtonProps } from './types/button-props.type'
```

- Экспортируй компоненты через named exports, а типы через `export type`.
- Не публикуй внутренние components, helpers, CSS Modules и промежуточные типы.
- Межюнитные consumers импортируют UI только через фасет.
- Не добавляй wrapper или alias, который только повторяет внутренний export.

Правила TSX и свойств компонентов находятся в [`styleguide/jsx-tsx.md`](../../styleguide/jsx-tsx.md), правила CSS
Modules — в [`styleguide/css.md`](../../styleguide/css.md). Реальная реализация находится в
[`examples/ui/button/`](../examples/ui/button/).

## Проверка

- У визуальной возможности есть самостоятельная ответственность и внешние consumers.
- Внутренние компоненты не превращены в юниты автоматически.
- Публичный фасет минимален и не раскрывает implementation details.
- Props и styles принадлежат тому же owner, что DOM и визуальное поведение.
- Компонент без DOM не получил искусственную визуальную структуру.
