# Ожидаемые доменные ошибки

Успешная операция возвращает доменный результат напрямую. Ожидаемый неуспешный исход выбрасывается как типизированное
доменное исключение. Публичная операция не передаёт потребителю исходную ошибку API-клиента, SDK или транспорта.

Не оборачивай успешный результат в `Result`, `{ ok, value }` или `{ data, error }`.

## Контракт ошибки

Ошибка содержит стабильный доменный код и только необходимые потребителю предметные данные:

```ts
export const PET_ERROR_CODE = {
  NOT_FOUND: 'PET_NOT_FOUND',
  TEMPORARILY_UNAVAILABLE: 'PET_TEMPORARILY_UNAVAILABLE',
} as const

export type PetErrorDetails =
  | Readonly<{
      code: typeof PET_ERROR_CODE.NOT_FOUND
      payload: Readonly<{ petId: string }>
    }>
  | Readonly<{
      code: typeof PET_ERROR_CODE.TEMPORARILY_UNAVAILABLE
    }>
```

- Код записывается в `SCREAMING_SNAKE_CASE` и является стабильной частью доменного контракта.
- Связь кода и данных описывается дискриминируемым объединением.
- Пустой `payload` не добавляется.
- `message` используется для диагностики, а не как пользовательский текст.
- Для каждой операции экспортируется отдельный тип ошибки только с допустимыми для неё кодами.

## Создание ошибки

Класс и фабрики остаются внутренними. Публичный фасет открывает коды, типы ошибок конкретных операций и функции их
проверки.

```ts
class PetDomainError extends Error {
  readonly name = 'PetDomainError'

  constructor(readonly details: PetErrorDetails) {
    super(`pet:${details.code}`)
  }
}

export const createPetNotFoundError = (petId: string): PetDomainError => {
  return new PetDomainError({
    code: PET_ERROR_CODE.NOT_FOUND,
    payload: { petId },
  })
}
```

Не собирай `details` рядом с каждым `throw`: именованная фабрика централизует код, данные и реализацию ошибки.

## Проверка во время выполнения

TypeScript не отражает тип выброшенной ошибки в `Promise<Pet>`, поэтому операция дополнительно экспортирует тип ошибки
и функцию проверки:

```ts
if (isGetPetError(error)) {
  handlePetError(error)
  return
}
```

Потребитель обрабатывает все коды контракта операции либо передаёт типизированную ошибку владельцу, который обеспечивает
исчерпывающую обработку. Не добавляй `default`, скрывающий расширение закрытого объединения.

Значение, которое не прошло проверку, обрабатывается по
[`failure-handling`](../../../quality/failure-handling.md). Не добавляй код `UNEXPECTED` в объединение доменных ошибок.

## Граница адаптера

Каждый адаптер определяет полный набор известных исходов источника для своей операции:

1. Успешный ответ источника преобразуется в доменный результат.
2. Ожидаемый исход источника преобразуется в зафиксированную доменную ошибку.
3. Неизвестная ошибка преобразуется в `ApplicationDefect`.

GET-хук сохраняет тот же контракт ошибок, что и GET-операция. Хук может разделить распознанную доменную ошибку и
неизвестный сбой для React-потребителя, но не создаёт новый набор кодов и не публикует ошибку источника.
