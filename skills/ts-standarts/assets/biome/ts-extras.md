# Проверки ts-extras в Biome

Перенесены диагностики 46 правил `prefer-ts-extras-*` из [`eslint-plugin-typefest@1.7.1`](https://www.npmjs.com/package/eslint-plugin-typefest/v/1.7.1)
для `ts-extras@3.0.0`. Для каждого правила одна и та же отмеченная строка проверена обоими линтерами. Из 46 правил
44 дают предупреждение, 2 — информацию для ревью. Правила для библиотеки `type-fest` в этот набор не входят.

**Как читать таблицу.** Имя слева — окончание исходного имени ESLint и часть кода `[TS-EXTRAS/имя]` в Biome.
«Прямо» означает проверку обычного вызова встроенной функции. «Частично» означает, что срабатывание ограничено
условиями справа. «Ревью» указывает на возможное отличие в поведении, а не на требование заменить код.
Чтобы [отключить одно замечание в приложении](README.md#как-отключить-замечание), используй имя из первого столбца.

## Границы переноса

- JavaScript-плагину Biome 2.6.9 доступны синтаксис и объявления в текущем файле, но не `TypeChecker` TypeScript.
  У 19 исходных правил указано `requiresTypeChecking: true`. Здесь распознаются литералы, явные аннотации параметров
  и переменных, локальные псевдонимы без параметров типа, обычные и `readonly`-массивы. Тип импортированного значения,
  сужение в произвольной ветке, перегрузки из других файлов и дополнения стандартных интерфейсов не разрешаются.
- Если тип получателя не установлен, одного имени `.length`, `.includes()`, `.filter()` или `.has()` недостаточно
  для замечания. Варианты с необязательным доступом, вычисляемыми именами методов и `...args` пропускаются.
- Автоматические исправления и вставка импортов из ESLint **не перенесены**. `biome check --write` не применяет
  эти предложения. Импортируй функцию из `ts-extras`, учитывая существующие псевдонимы, и проверь сужение через `tsc`.
  Плагин применяется в проектах, использующих `ts-extras@3`; он не определяет версию зависимости по `node_modules`.

## Массивы и фильтры

| Правило | Перенос | Когда появляется замечание |
| --- | --- | --- |
| `is-empty` | Частично | У массива `xs.length === 0` или `== 0`, в том числе `0 === xs.length`. Также `!xs.length`. |
| `is-non-empty` | Частично | `> 0`, `>= 1`, `!== 0`, `!= 0`, в том числе с обратным порядком; также `if (xs.length)`. Длина кортежа пропускается. |
| `has-at-least` | Частично | Минимум от 2 до 999, заданный целым литералом: `xs.length >= 2` или `1 < xs.length`. Получение размера, индекс цикла и именованный лимит остаются без замечания. |
| `array-is-array` | Частично | `Array.isArray(x)` для `unknown` или известного типа с `readonly`-массивом. Проверяет контейнер, не элементы. |
| `array-at` | Частично | `.at(index)` у массива с числовым аргументом. |
| `array-first` | Частично | Чтение `tuple[0]` у известного кортежа. Обычный `ids[0]` после проверки непустоты допустим. |
| `array-last` | Частично | `tuple[tuple.length - 1]` для того же имени кортежа. Запись по индексу и вызов метода через индекс не заменяются. |
| `array-concat` | Частично | `.concat()` у массива с известными массивами или аргументами типов `string`, `number`, `boolean`. |
| `array-includes` | Частично | `.includes(value)` для известного массива и подходящего значения; необязательное смещение должно быть числом. |
| `array-index-of` | Частично | `.indexOf(value)` у массива, а не у строки или произвольного объекта. |
| `array-last-index-of` | Частично | `.lastIndexOf(value)` с теми же ограничениями, что у `array-index-of`. |
| `array-join` | Частично | `.join()` или `.join(separator)` со строковым разделителем у массива с известными строками, числами, логическими значениями или пропусками `null`/`undefined`. Массивы символов пропускаются. |
| `is-defined-filter` | Частично | `.filter(v => v !== undefined)` или проверка `typeof` у параметра. Затенённый `undefined` пропускается. |
| `is-present-filter` | Частично | `.filter(v => v != null)` или исключение сразу `null` и `undefined`. Сравнение только с `null` через `!==` не заменяется. |
| `is-truthy` | Частично | `.filter(Boolean)` на массиве с явно указанным типом, из которого можно убрать ложные значения. Предлагается `isTruthy`, не `isPresent`. |
| `is-property-defined` | Частично | Строгая проверка поля на `undefined` в `.filter()` непосредственно у массива объектных литералов с этим собственным полем данных. |
| `is-property-present` | Частично | Проверка поля на `!= null` в том же случае. Для произвольной записи поле могло бы быть геттером или унаследованным. |
| `not` | Частично | `.filter(v => !guard(v))`, если локальный `guard` явно принимает `unknown` и возвращает предикат типа. Обычная функция с результатом `boolean` пропускается. |

## Значения, строки, числа и объекты

| Правило | Перенос | Когда появляется замечание |
| --- | --- | --- |
| `is-defined` | Частично | Сравнение переменной с глобальным `undefined` через `===`/`!==`, либо `typeof` для объявленного имени. |
| `is-present` | Частично | `x != null`, `x == null` и пары строгих сравнений одной переменной; `x != undefined` тоже исключает **оба** значения. |
| `is-finite` | Прямо | `Number.isFinite(x)` с одним аргументом; локальный `Number` пропускается. |
| `is-integer` | Прямо | `Number.isInteger(x)` с теми же условиями. |
| `is-safe-integer` | Прямо | `Number.isSafeInteger(x)` с теми же условиями. |
| `is-infinite` | Частично | Одно имя строго сравнивается с обеими бесконечностями через `\|\|`. Одностороннюю проверку оставь без замены. |
| `string-starts-with` | Частично | `.startsWith(prefix)` у известной строки; префикс строковый, позиция, если есть, числовая. |
| `string-ends-with` | Частично | `.endsWith(suffix)` при таких же условиях. |
| `string-split` | Частично | `.split()` или разбиение строки по строковому разделителю. Случаи с регулярным выражением оставлены без предложения. |
| `map-has` | Частично | `.has(key)` у известного `Map`/`ReadonlyMap`. Сужение касается ключа, не результата `get`. |
| `set-has` | Частично | `.has(value)` у известного `Set`/`ReadonlySet`. Смешанные получатели и неоднозначные типы значения пропускаются. |
| `object-keys` | Частично | `Object.keys(obj)` с известным объектным аргументом. |
| `object-values` | Частично | `Object.values(obj)` с тем же ограничением. |
| `object-entries` | Частично | `Object.entries(obj)` с тем же ограничением. |
| `object-from-entries` | Частично | `Object.fromEntries(entries)` с известным массивом или `Map`; произвольный итерируемый объект пропускается. |
| `object-assign` | Частично | `Object.assign(target, source)` с известным объектом и источниками — простыми литералами, без геттеров, `...` или ключа `__proto__`. |
| `object-has-own` | Частично | `Object.hasOwn(obj, key)`, если получатель известен как объект или коллекция, а не как возможный `null`. |
| `object-has-in` | Частично | `Reflect.has(obj, 'key')` с известным объектом и строковым ключом, кроме `constructor` и `__proto__`. |
| `key-in` | Частично | `key in obj` для переменной с объединением строковых ключей и объекта из простого литерала. Выбор ветки по полю-признаку у произвольного объекта не меняется. |
| `object-map-values` | Частично | `objectFromEntries(objectEntries(obj).map(([k, v]) => [k, …]))` с неизменным ключом и простым объектом. Проверяется источник именованных импортов, включая псевдонимы. |

## Утверждения и операции с типами

| Правило | Перенос | Когда появляется замечание |
| --- | --- | --- |
| `assert` | Частично | `if (!ok)` без `else`, с единственным `throw new Error` и без динамического сообщения. |
| `assert-defined` | Частично | `if (x === undefined)` с единственным `throw new TypeError`. Сохрани класс исключения и сообщение. |
| `assert-present` | Частично | Та же форма при отсутствии `null` или `undefined`. Предметное исключение не заменяется. |
| `assert-error` | Ревью | `if (!(x instanceof Error))` с `throw new TypeError`. `assertError` распознаёт также некоторые ошибки из другого контекста JavaScript: поведение не тождественно. |
| `assert-never` | Ревью | Неиспользуемое и неэкспортируемое `const x: never = value`. `assertNever` добавит исключение во время выполнения; `satisfies never` остаётся допустимым. |
| `as-writable` | Частично | `x as Writable<typeof x>` или форма с угловыми скобками. `Writable` должен быть именованным импортом из `type-fest`. |
| `safe-cast-to` | Частично | Приведение к `string`, `number` или `boolean`, когда совместимость видна локально. `unknown as T` и `as const` не трогаются. |
| `is-equal-type` | Частично | Локальная неиспользуемая `const` с типом `IsEqual<A, B>` из `type-fest` и литералом `true`/`false`. Сохрани ожидание через `satisfies`; `isEqualType` не возвращает логическое значение при выполнении. |
