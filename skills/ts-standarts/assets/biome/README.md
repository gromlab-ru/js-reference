# Форматирование и линт TypeScript через Biome

Один [профиль](ts.json) задаёт формат и правила линтера для `.ts`, `.mts` и `.cts`. Он подключает [правила типов](rules.js)
и [проверки применения `ts-extras`](ts-extras/index.js). Проверено с `@biomejs/biome@2.6.9`. API плагинов предоставляет
CLI; сами проверки не требуют ESLint, TypeScript или `@biomejs/runtime` во время запуска Biome.

## Подключение

Из корня приложения установи проверенную версию CLI. Используй одну версию в редакторе, локально и в CI.
Если проект также применяет скилл `jsdoc-standarts`, выбирай сборку Biome, совместимую с обоими профилями:
у плагина для чтения JSDoc есть отдельные требования.

```sh
npm install --save-dev --save-exact @biomejs/biome@2.6.9
```

Скопируй пресет и оба плагина. Здесь `SKILL` — путь к установленному скиллу; в этом репозитории это `./skills/ts-standarts`.

```sh
SKILL=./.agents/skills/ts-standarts
mkdir -p tools/ts-standarts
cp "$SKILL/assets/biome/ts.json" "$SKILL/assets/biome/rules.js" tools/ts-standarts/
cp -R "$SKILL/assets/biome/ts-extras" tools/ts-standarts/
if [ ! -f tools/ts-standarts/ts-extras.settings.js ]; then
  cp "$SKILL/assets/biome/ts-extras.settings.js" tools/ts-standarts/
fi
```

Создай `biome.json` в корне приложения. Если уже есть `biome.json` или `biome.jsonc`, добавь путь в его `extends`,
сохранив настройки проекта. Если скилл доступен в CI, можно сразу указать путь к его `assets/biome/ts.json`.

```json
{
  "extends": ["./tools/ts-standarts/ts.json"]
}
```

`resolutionKind: "config"` позволяет найти оба плагина рядом с профилем. Обновляй их вместе с `ts.json`. Профиль дополняет
правила проекта; на JavaScript, JSX, TSX и другие языки его настройки не распространяются.

## Команды

Из корня приложения запусти нужную проверку; вместо `src` можно передать каталог или конкретный файл.

| Команда | Когда использовать |
| --- | --- |
| `npx biome format --write src` | Применить форматирование. |
| `npx biome lint src` | Получить замечания линтера без изменения файлов. |
| `npx biome check src` | Проверить формат, линт и включённые действия, в том числе порядок импортов. Подходит для CI. |

Для проверки подключения напиши `type Flight = { flightId: string }` в файле `.ts`. Линтер выдаст
`[TS-OBJECT-LINES]`. Перенеси поле на строку после `{` и выполни форматирование. Повторная проверка должна пройти.

## Что проверяется

- **Форматтер:** два пробела, ориентир 120 символов, одинарные кавычки, скобки стрелки по необходимости,
  точки с запятой только для разделения инструкций, без завершающих запятых. Короткий объект-значение допустим
  в одну строку; Biome сохраняет развёрнутую форму объекта с переносом перед первым полем.
- **Встроенный линтер:** `const` при отсутствии переназначения, запрет `var`, фигурные скобки у веток и циклов,
  лишний `else`, импорты и экспорты типов, опасный выход из `finally`. Регистр проверяется у объявлений типов,
  классов, перечислений и их членов, переменных и функций. У `const` на уровне модуля допустимы оба регистра:
  смысловой выбор между `flightId` и `MAX_PAGE_SIZE` остаётся за автором.
- **`[TS-NAMED-OBJECT]`:** объект прямо в объединении, пересечении или аннотации параметра нужно назвать.
  Перенос полей по строкам не заменяет имени. Объединение литералов, именованные части и литералы значений допустимы.
- **`[TS-OBJECT-LINES]`:** непустой объектный тип или интерфейс не записывается целиком на одной строке.
- **`[TS-ARRAY]`:** простой элемент — `T[]` или `readonly T[]`; явно записанное объединение — `Array<A | B>`
  или `ReadonlyArray<A | B>`. Встроенное правило с одной формой для всех массивов здесь выключено.
- **`[TS-EXTRAS/…]`:** 44 проверки предлагают подходящую функцию; ещё две (`assert-error`, `assert-never`) выдают
  информацию об изменении поведения. См. [результат переноса каждого из 46 правил](ts-extras.md). Автоисправлений
  у них нет. Чтобы предупреждения завершали CI с ошибкой, используй `npx biome ci --error-on-warnings src`.

Плагин показывает место ошибки, но не придумывает имя и не переписывает тип. Между самостоятельными объявлениями
проверяй пустую строку при ревью: форматтер не вставляет все такие разделители. Выбор между `function` и стрелкой,
смысл имён и поведение вызываемого кода проверяй по [правилам кода](../../reference/code.md)
и [правилам типов](../../reference/types.md). Для проверки совместимости типов запускай `tsc` проекта.

## Как отключить замечание

**Одно правило `ts-extras` во всём приложении.** В копии профиля открой
`tools/ts-standarts/ts-extras.settings.js` и укажи имя из сообщения без префикса `TS-EXTRAS/`:

```js
export const disabledRules = new Set(['is-non-empty'])
```

Теперь `ids.length > 0` не даёт `[TS-EXTRAS/is-non-empty]`, а `ids.length === 0` по-прежнему даёт
`[TS-EXTRAS/is-empty]`. Так же можно отключить информационную подсказку, например `assert-error`. Убери имя из
списка, чтобы вернуть замечание. Команды подключения выше сохраняют этот файл при обновлении. При прямом `extends`
из установленного скилла сначала скопируй профиль в приложение, чтобы настройка касалась только него.

**Одно место в исходнике.** Для встроенного правила используй его категорию: например, `// biome-ignore lint/style/useConst: причина`.
У JavaScript-плагина Biome 2.6.9 комментарий выбирает экспортированную **группу** проверок, а не код в квадратных
скобках. Например, следующая запись скрывает сообщения группы `comparisons` только на строке `return`:

```ts
export const hasFlights = (ids: readonly string[]): boolean => {
  // biome-ignore lint/plugin/comparisons: Эту функцию передаём в среду без импорта ts-extras.
  return ids.length > 0
}
```

Для `assert-error` соответствующая группа — `conditions`. Поставь комментарий перед строкой, на которой начинается
подсвеченное выражение. Добавлять `TS-EXTRAS/is-non-empty` как ключ в `linter.rules` не нужно: это имя проверки
нашего профиля, а не встроенное правило Biome.
