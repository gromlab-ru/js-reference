# JSDoc для объектов, интерфейсов и перечислений

Читатель должен понять, что описывает объявление целиком, а при обращении к отдельному члену — что означает именно он.

## Шаблон

Над объектом, интерфейсом или `enum` поставь многострочный JSDoc. Первая фраза обязательна. Второй абзац нужен,
только если есть общее условие, без которого легко ошибиться при использовании.

```text
/**
 * <Что представляет объявление и для чего его используют.>
 *
 * <Что важно для использования или понимания объявления целиком.>
 */
```

У каждого поля объекта или интерфейса поясни его собственное назначение:

```text
<объект или интерфейс> {
  /** <Назначение поля, при необходимости — единицы измерения.> */
  <поле>

  /**
   * <Назначение поля.>
   *
   * - <особое значение> — <что оно означает>
   * - <диапазон> — <что он означает>
   */
  <поле с особыми значениями>
}
```

## Правила

1. Сформулируй первую фразу по виду объявления:
   - Для объекта укажи, какие данные он хранит или описывает и для какой задачи они нужны.
   - Для интерфейса опиши один экземпляр. Если главное в нём — методы, назови гарантию, общую для всех реализаций.
   - Для перечисления укажи, что означает одно значение и где его используют.
2. Поставь JSDoc непосредственно перед каждым полем объекта или интерфейса. Короткую подпись пиши в виде `/** … */`,
   длинную фразу [переноси по общему правилу](../SKILL.md#перенос-строк). Имя поля уже видно в объявлении.
   Не повторяй его отдельным заголовком и не дублируй описание сверху через `@property`.
3. Если у поля есть неочевидные значения или диапазоны, разверни его JSDoc на несколько строк. Начни с назначения,
   оставь пустую строку и перечисли особые случаи в виде «значение — смысл». Даже одно пояснение оформи отдельным
   пунктом. Ставь `-` сразу после `* `, на одном уровне с описанием поля.
4. Если от одного поля зависит смысл другого, опиши связь у поля, которое задаёт условие. Если расшифровка уже есть
   у общего типа, сошлись на него.
5. Метод интерфейса или член `enum` подпиши одной строкой `/** … */`. У члена `enum` поясни смысл кода: сам код уже
   виден в объявлении. Над перечислением уместны общие условия: например, зарезервированный код или допустимость
   сочетания флагов.

## Примеры

### Объект: данные аккаунта для проверки входа

```ts
/**
 * Схема данных аккаунта, по которым сервер проверяет право на вход.
 */
export const LOGIN_ACCOUNT = ACCOUNT.extend({
  /** Сохранённый хеш для проверки пароля на сервере; не возвращать клиенту. */
  passwordHash: z.string(),

  /**
   * Уровень доступа аккаунта.
   *
   * - меньше нуля — вход запрещён
   * - ноль — обычный аккаунт
   * - больше нуля — права конкретного уровня определяет сервер
   */
  accessLevel: z.int(),

  /**
   * Дата и время окончания блокировки.
   *
   * - `null` — блокировку не задавали или сняли
   * - дата в будущем — блокировка действует до этой даты
   * - истёкшая дата — срок блокировки закончился,
   *   но дата может оставаться в базе
   */
  bannedUntil: z.date().nullable(),

  /**
   * Последний мир, который игроку разрешили выбрать.
   *
   * - `1` — возможное начальное значение;
   *   оно не подтверждает вход игрока в этот мир
   */
  lastServerId: SERVER_ID
})
```

### Интерфейс: условия тарифа

```ts
/**
 * Условия перевозчика для расчёта платы за одну отправку.
 */
export interface DeliveryTariff {
  /** Ставка в копейках за килограмм. */
  ratePerKg: number

  /**
   * Верхний предел платы за одну отправку в копейках.
   *
   * - `null` — верхнего предела нет; плату рассчитывают по ставке
   * - `0` — доставка бесплатна независимо от ставки
   * - положительное значение — плату рассчитывают по ставке,
   *   но итоговая сумма не может превысить этот предел
   */
  capKopecks: number | null
}
```

### Перечисление: маршрут посылки

```ts
/**
 * Маршрут посылки в журнале сортировщика.
 *
 * Номера выходов не задают порядок обработки. Выход 2 зарезервирован.
 */
export enum SortingRoute {
  /** Выход ещё не назначен. */
  Unassigned = 0,

  /** Посылка остаётся для выдачи на этой станции. */
  Local = 1,

  /** Посылка направлена на следующую станцию. */
  Transfer = 3
}
```

## Проверка

- **Прочитай только первую фразу.** Понятно ли, что это и зачем нужно? Например, у `DeliveryTariff` сразу видно,
  что это условия перевозчика для расчёта платы за одну отправку.
- **Прочитай только JSDoc поля.** Можно ли при наведении на `tariff.capKopecks` понять, что `null` снимает верхний
  предел, а `0` делает доставку бесплатной? В примере объекта найди у `lastServerId` ответ
  на вопрос: подтверждает ли `1`, что игрок уже входил в этот мир?
- **Прочитай подпись отдельно, как при наведении.** Что означает `SortingRoute.Transfer` в журнале?
  Из подписи должно быть понятно, что посылку направили на следующую станцию. Ответ на вопрос «почему нет выхода 2?»
  находится во втором абзаце над `SortingRoute`: он относится к набору кодов целиком.
