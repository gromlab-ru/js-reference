# JSDoc для констант

Читатель должен понимать, что означает именованное значение и в какой ситуации его использовать.
Это может быть задержка, лимит, код или значение по умолчанию.

## Шаблон

```text
/**
 * <Что задаёт значение и для какой задачи оно нужно.>
 *
 * <Условие применения, если без него легко ошибиться.>
 */
export const <ИМЯ> = <значение>
```

## Правила

1. Поставь многострочный JSDoc перед объявлением константы, даже если достаточно одной фразы.
   Для величины укажи единицы измерения и уточни, к чему она относится: например, задержка в миллисекундах перед
   повторной отправкой одной заявки.
2. Добавь второй абзац, только если он помогает правильно применить значение. Для лимита поясни, что в него входит;
   для значения по умолчанию — когда его выбирают. Не переписывай литерал из объявления и не придумывай, почему он выбран.
3. Выбирай шаблон по тому, как используют `const`. Для стрелки нужен [JSDoc функции](function.md), для объекта
   с полями, в том числе с `as const`, — [JSDoc объекта](object-interface-enum.md). Не ставь JSDoc у промежуточного
   результата только потому, что он записан в `const`.

## Примеры

### Задержка перед повтором

```ts
/**
 * Пауза в миллисекундах перед повторной отправкой заявки перевозчику.
 */
export const DELIVERY_RETRY_DELAY_MS = 30_000
```

### Лимит на одну заявку

```ts
/**
 * Максимальное число попыток передать одну заявку перевозчику.
 *
 * В лимит входят и первая отправка, и её повторы.
 */
export const MAX_DELIVERY_ATTEMPTS = 3
```

## Проверка

- Применять ли `DELIVERY_RETRY_DELAY_MS` перед первой отправкой? Нет: эта задержка относится к повтору.
- Первая отправка не удалась. Сколько попыток осталось при `MAX_DELIVERY_ATTEMPTS = 3`? Две. Из одного названия
  неясно, входит ли первая попытка в лимит; второй абзац даёт ответ.
