# JSDoc для функций и методов

Читатель должен понимать, зачем вызывать функцию, что ей передать и что вернётся или изменится после вызова.
Если функцию используют как React-компонент в JSX, примени [шаблон компонента](react-component.md#шаблон).

## Шаблон

```text
/**
 * <Назначение функции одним предложением.>
 *
 * <Неочевидное поведение вызова, если оно есть.>
 *
 * `<первый аргумент>`: <для чего он нужен>.
 *
 * `<второй аргумент>`: <для чего он нужен>.
 *   - <значение или условие> — <его смысл и результат вызова>
 *   - `<тип>` при <условии> — <что происходит в этом случае>
 */
```

## Правила

1. Поставь многострочный JSDoc перед объявлением функции или метода с реализацией. У стрелочной функции в переменной
   ставь его перед `const`. Начни с назначения. Если вызов меняет переданные данные или даёт неочевидный результат, поясни это.
   Этот же шаблон используй для геттеров, сеттеров и генераторов.
   Для метода, объявленного в интерфейсе, используй [правило подписи члена интерфейса](object-interface-enum.md#правила).
2. **Один аргумент — один абзац.** Опиши все аргументы в порядке вызова, включая необязательные. Для именованного
   аргумента начни с точного имени в обратных кавычках и двоеточия. Если объект или массив разобран прямо в сигнатуре,
   начни с `Аргумент N:` обычным текстом, без обратных кавычек. Считай позиции с 1, включая именованные аргументы.
   После двоеточия на той же строке объясни назначение без тегов. Укажи единицы, если они важны. Длинную фразу
   [переноси по общему правилу](../SKILL.md#перенос-строк). Между аргументами оставляй пустую строку ` *`.
3. Добавь пункт под описанием аргумента, если без пояснения читатель может неверно предсказать результат вызова.
   Слева от тире укажи значение или условие: например, пропуск необязательного аргумента, ответ или ошибку переданной
   функции. Справа поясни, что это означает и что произойдёт. После `* ` добавь два пробела перед `-`.
   Если строки с назначением достаточно, список не нужен.
4. Если варианты объединения обрабатываются по-разному, называй их как в сигнатуре: например, `null` и `Date`.
   Если внутри одного варианта результат зависит от условия, повтори метку типа и укажи условие в каждом пункте.
   Объясни все случаи с разным смыслом или поведением. Значения с общим правилом можно объединить в диапазон.
   Если тип не влияет на поведение, не пересказывай сигнатуру.
5. Если аргументов нет, пропусти эту часть комментария. У перегрузки сверяй аргументы с её публичной сигнатурой.

При деструктуризации не копируй шаблон из сигнатуры и не придумывай для него имя `options`. Если поведение вызова
зависит от одного поля, назови его так, как его передаёт вызывающий код: `limit`, а не локальное `size`.
Для массива укажи значимую позицию элемента. Ни поля, ни элементы не становятся отдельными аргументами.
Общий смысл данных оставь у [их типа](type.md).

## Примеры

### Оставшееся время блокировки входа

```ts
/**
 * Вычисляет, сколько миллисекунд осталось до конца временной блокировки входа.
 *
 * Расчёт предполагает корректные даты.
 *
 * `bannedUntil`: дата окончания блокировки из записи аккаунта.
 *   - `null` — блокировку не задавали или сняли; функция вернёт `0`
 *   - `Date` при `bannedUntil <= checkedAt` — срок истёк; функция вернёт `0`
 *   - `Date` при `bannedUntil > checkedAt` — блокировка действует;
 *     функция вернёт число миллисекунд до её окончания
 *
 * `checkedAt`: время на сервере в момент проверки входа.
 */
export const getRemainingBanMs = (bannedUntil: Date | null, checkedAt: Date): number =>
  bannedUntil === null ? 0 : Math.max(0, bannedUntil.getTime() - checkedAt.getTime())
```

### Вызов меняет переданную очередь

```ts
/**
 * Забирает следующую заявку на отправку.
 *
 * `queue`: идентификаторы заявок в порядке отправки.
 *   - `[]` — заявок нет; функция вернёт `undefined`
 *   - `queue.length > 0` — функция вернёт первый идентификатор,
 *     удалив его из переданной очереди
 */
export function takeNext(queue: string[]): string | undefined {
  return queue.shift()
}
```

### Деструктуризация аргумента

```ts
/**
 * Настройки выборки одной партии заявок из очереди.
 */
export type BatchOptions = {
  /** Максимальное число заявок в партии: целое, не меньше нуля. */
  limit?: number
}

/**
 * Возвращает первую партию заявок, не меняя очередь.
 *
 * `queue`: идентификаторы заявок в порядке отправки.
 *
 * Аргумент 2: настройки размера партии.
 *   - `limit` не задан — вернётся не больше 20 заявок
 *   - отрицательный или нецелый `limit` — функция выбросит `RangeError`
 */
export function readBatch(queue: readonly string[], { limit: size = 20 }: BatchOptions): string[] {
  if (!Number.isInteger(size) || size < 0) {
    throw new RangeError('Размер партии должен быть целым неотрицательным числом')
  }

  return queue.slice(0, size)
}
```

У `readBatch(queue, {})` два аргумента: объект настроек передан, а поле `limit` — нет. Чтобы прочитать только
первую заявку, вызови `readBatch(queue, { limit: 1 })`. Имя `size` знать не нужно.

### Асинхронный вызов с запасной ставкой

```ts
/**
 * Возвращает ставку перевозчика в копейках за килограмм.
 *
 * `load`: запрашивает действующую ставку у перевозчика.
 *   - `0` в ответе — доставка бесплатна; `lastKnown` не используется
 *   - ошибка запроса — функция вернёт `lastKnown`
 *
 * `lastKnown`: последняя известная ставка этого перевозчика.
 */
export async function readDeliveryRate(load: () => Promise<number>, lastKnown: number): Promise<number> {
  try {
    return await load()
  } catch {
    return lastKnown
  }
}
```

## Проверка

1. Закрой тело `takeNext`. В очереди `['A', 'B']`. Что получит вызывающий код и что останется в той же очереди?
   Комментарий должен дать оба ответа: вернётся `'A'`, в очереди останется `['B']`.
2. Сверь абзацы с сигнатурой: у именованного аргумента должно совпасть имя, у разобранного объекта или массива —
   номер позиции. Проверь, можно ли собрать вызов по описанию, не заглядывая в тело функции.
3. Сверь обещанное поведение с реализацией. Если есть граница, проверь значения до неё, на ней и после.
   У `getRemainingBanMs` за секунду до окончания блокировки ожидается `1000`, в момент окончания и после него — `0`.
   Если комментарий пропускает случай, допускает два разных ответа или расходится с кодом, приведи в замечании
   конкретный вход, на котором это видно.
