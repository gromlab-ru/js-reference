# JSDoc для React-компонентов

Читатель должен понять по комментарию над компонентом, что увидит пользователь или какое действие сможет выполнить.
Раздел `Используется для:` помогает решить, подходит ли компонент для конкретной задачи.

## Шаблон

```text
/**
 * <Назначение компонента в одной строке>.
 *
 * Используется для:
 *  - <сценарий применения>
 */
```

## Правила

1. Поставь многострочный JSDoc перед объявлением компонента. Первую фразу начни с его назначения.
   Например, «Показывает стоимость доставки» полезнее, чем «Возвращает JSX с ценой».
2. После пустой строки напиши `Используется для:` и приведи от одного до трёх сценариев. Каждый пункт должен отвечать
   на вопрос «В какой ситуации выбрать этот компонент?». Если сценарий один, одного пункта достаточно.
3. Описывай свойства у их объявлений [по правилам полей](object-interface-enum.md#правила). Для обработчика поясни,
   когда компонент его вызовет и что передаст. Над компонентом не повторяй список свойств и не добавляй абзац
   `props:` или `Аргумент 1:`: в JSX свойства передают по именам.
4. Раздел `Используется для:` относится только к JSDoc компонента. Для хука, обработчика или вспомогательной функции
   используй [правила функций](function.md).

## Пример

JSDoc над компонентом `DeliveryFee`:

```tsx
/**
 * Показывает покупателю стоимость одного способа доставки.
 *
 * Используется для:
 *  - сравнения способов доставки при оформлении заказа
 */
```

## Проверка

- Прочитай только верхний комментарий. Зачем показывать `DeliveryFee` у каждого способа доставки?
  Чтобы покупатель мог сравнить стоимость вариантов до выбора.
- Прочитай JSDoc свойства отдельно. Например, можно ли по описанию `feeKopecks` понять, что передать, пока цена
  неизвестна, и чем это отличается от бесплатной доставки?
