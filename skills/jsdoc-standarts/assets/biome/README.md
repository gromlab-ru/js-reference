# Проверка JSDoc через Biome

[Готовый конфиг](jsdoc.json) уже подключает [плагин](jsdoc.js). Отдельный пакет плагина и `@biomejs/runtime` в проекте
не нужны: Biome сам предоставляет API во время запуска.

## 1. Выбери совместимый CLI

Проверено на [сборке Biome из коммита `426c33de575da7ce7f4588727b9367125dfa6827`](https://github.com/biomejs/biome/actions/runs/44840917605).
В стабильной **2.6.8** нет метода `leadingTrivia()` для чтения JSDoc перед объявлением. На этой версии профиль
завершает проверку TS/TSX с ошибкой `[JSDOC-API]`, а не выдаёт отсутствие замечаний за успешную проверку.
Метод появился [после этого релиза](https://github.com/biomejs/biome/pull/13195).

Можно скачать готовый CLI из указанной сборки. Например, на Linux x64 с glibc из корня проекта:

```sh
gh run download 44840917605 --repo biomejs/biome \
  --name cli-x86_64-unknown-linux-gnu --dir .tools/biome-426c33d
chmod +x .tools/biome-426c33d/biome-linux-x64
export BIOME_BINARY="$PWD/.tools/biome-426c33d/biome-linux-x64"
```

Для другой платформы выбери её архив в том же запуске и укажи путь к распакованному CLI. Если архив уже недоступен,
можно собрать тот же коммит из исходников с Rust по `rust-toolchain.toml` репозитория Biome:

```sh
cargo install --git https://github.com/biomejs/biome \
  --rev 426c33de575da7ce7f4588727b9367125dfa6827 --locked --root .tools/biome-426c33d biome_cli
export BIOME_BINARY="$PWD/.tools/biome-426c33d/bin/biome"
```

Используй одну версию CLI локально, в CI и в расширении редактора. Команды ниже запускают выбранный двоичный файл напрямую.

## 2. Подключи профиль

`SKILL` ниже — путь к установленному `jsdoc-standarts`, например `./.agents/skills/jsdoc-standarts`. В этом репозитории
это `./skills/jsdoc-standarts`. Команды выполняются в проекте, который нужно проверять.

**Если `biome.json` уже есть**, положи оба ресурса рядом и добавь пресет к существующему `extends`:

```sh
SKILL=./.agents/skills/jsdoc-standarts
mkdir -p tools/jsdoc
cp "$SKILL/assets/biome/jsdoc.json" "$SKILL/assets/biome/jsdoc.js" tools/jsdoc/
```

```json
{
  "extends": ["./tools/jsdoc/jsdoc.json"]
}
```

`resolutionKind: "config"` в пресете означает, что Biome найдёт `./jsdoc.js` рядом с пресетом независимо от рабочей
директории. Имя `jsdoc.json` не создаёт вторую точку входа при проверке всего проекта. Профиль включает линтер и
`useSingleJsDocAsterisk`, не задаёт базовый набор правил и не меняет ширину кода, форматтер и набор файлов проекта.

**Если конфига ещё нет**, тот же файл можно использовать как основной `biome.json`:

```sh
SKILL=./.agents/skills/jsdoc-standarts
cp "$SKILL/assets/biome/jsdoc.json" ./biome.json
cp "$SKILL/assets/biome/jsdoc.js" ./jsdoc.js
```

Обновляй конфиг и плагин вместе. Если в проекте уже установлен скилл и его ресурсы доступны в CI, можно указать путь
к `assets/biome/jsdoc.json` прямо в `extends`, без копирования.

## 3. Проверь подключение

```sh
"$BIOME_BINARY" lint src
```

Для всей обычной проверки проекта используй `"$BIOME_BINARY" check src`. Замени `src` на свой каталог. В качестве
быстрой пробы убери JSDoc над именованной функцией или переименуй только аргумент: должны появиться соответственно
`[JSDOC-MISSING]` или `[JSDOC-ARGS]`. После восстановления исходника замечание исчезнет.

## Что проверяется

| Код замечания | Что проверяет плагин |
| --- | --- |
| `MISSING`, `BLOCK`, `SUMMARY` | Перед объявлением есть непустой JSDoc. У типа, интерфейса, константы, класса, функции, конструктора и компонента он многострочный. У поля допустимы обе формы, а у члена `enum` и метода интерфейса — однострочная подпись. |
| `ARGS`, `PARAGRAPH` | У каждого аргумента есть отдельный абзац с пояснением. Проверяются имя, порядок, необязательные параметры, `...rest` и метки `Аргумент N:`. В нумерацию входит каждый аргумент вызова, но не параметр TypeScript `this`. |
| `LIST` | Для записанных особых случаев есть условие, тире и пояснение. У аргумента проверяются вложенный отступ и перенос продолжения, у поля — список без дополнительного отступа. |
| `REACT` | В TSX над компонентом есть строка назначения, пустая строка и 1–3 сценария `Используется для:`. Сценарии оформлены как в шаблоне компонента. У обычной функции этот раздел не требуется и не заменяет описание аргументов. |
| `TAGS` | В `@param {…}`, `@returns {…}` и `@type {…}` не повторяется тип TypeScript. У объектного объявления нет второго списка полей `@property`. |

**Область действия.** Плагин работает с `.ts`, `.tsx`, `.mts` и `.cts`. Проверяет именованные объявления функций,
стрелки и функции в переменных, перегрузки, конструкторы, методы и поля классов. У перегрузок достаточно описать
публичные сигнатуры. Параметр-свойство описывается в JSDoc конструктора. У `type` проверяются также сигнатуры функций
и поля объектных частей `A & { … }` и `A | { … }`.

У констант верхнего уровня проверяются экспорты, имена вида `BATCH_LIMIT` и значения с уже написанным JSDoc.
Промежуточным локальным значениям и безымянным обработчикам JSDoc не навязывается. Поля именованного объекта
проверяются в литерале, под `as const` и `satisfies`, а также в непосредственном аргументе `Object.freeze`,
`z.object` и `.extend`/`.safeExtend`. Плагин не ищет поля в результатах произвольных вызовов.

Компонент определяется по синтаксису: например, функция `DeliveryFee` в TSX возвращает JSX, имеет аннотацию
`JSX.Element` или обёрнута в `memo`/`forwardRef`. Для именованной функции с заглавной буквы и непрозрачным результатом
раздел `Используется для:` явно выбирает формат компонента. Плагин не разрешает импорты и не выводит тип результата
за компилятор TypeScript.

**Дополнительные теги.** После основного описания можно поставить `@example`, `@throws {RangeError}`, `@see`,
`@deprecated`, `@returns` с пояснением, `@template`, собственный тег или дополнительный `@param id` для подсказки
параметра. Белого списка тегов нет. `{@link …}` допустим и в основном тексте. Теги не удаляются и не заменяют
согласованные абзацы аргументов. Код внутри ограждений Markdown не проверяется как текст JSDoc. Если отдельный
каталог целиком использует другой стандарт документации, добавь к `includes` **этого плагина** исключение,
например `!**/vendor/**`: остальные проверки Biome продолжат действовать.

**Граница проверки.** Плагин выдаёт замечания без автоисправлений. Он не определяет, правдиво ли описание, какое
значение нужно было расшифровать или как следует перенести фразу около 80-й колонки. Это проверяется
[при ревью](../../reference/review.md).

В репозитории скилла интеграционные тесты запускаются командой `npm run test:jsdoc-biome` при заданном `BIOME_BINARY`
или с совместимым `biome` в `PATH`. Тесты используют настоящие `biome lint` и `biome check` во временных проектах.
