# Юниты

Юнит — единственная рекурсивная граница владения в Unit Architecture.

## Обязательные свойства

Каждый юнит:

- владеет одной связной ответственностью;
- находится в отдельной папке;
- имеет хотя бы один непустой фасет;
- определяет один логический публичный API;
- владеет своими архитектурными зависимостями;
- скрывает внутреннюю реализацию;
- является узлом графа зависимостей.

```text
header/
├── index.ts      # Непустой фасет
└── ...           # Свободная внутренняя структура
```

Наличие фасета необходимо, но недостаточно. Папка с `index.ts`, которая не владеет отдельно сформулированной ответственностью, остаётся внутренней организацией и не должна объявляться юнитом.

## Внутренняя свобода

Unit Architecture не устанавливает, какие файлы и сегменты должен содержать юнит. Допустимы, например, обе формы:

```text
header/
├── index.ts
├── header.tsx
├── styles/
│   └── header.module.css
└── types/
    └── header.type.ts
```

```text
header/
├── index.ts
├── header.tsx
├── ui/
├── providers/
├── styles/
├── types/
├── hooks/
├── libs/
├── utils/
└── stores/
```

Эти деревья выражают одну и ту же архитектурную границу. Второй набор сегментов используется в примерах только для демонстрации внутренней свободы. Выбор имён, содержимого и структуры сегментов принадлежит команде приложения.

## Что не создаёт юнит

Ни один из сигналов сам по себе не обосновывает новый юнит:

- отдельный framework-компонент;
- Provider, Guard, hook или service;
- папка со стилями и типами;
- большое количество строк;
- локальное состояние;
- повторное использование;
- технический `index.ts`;
- место в runtime-дереве UI.

Новый юнит появляется только для отдельной ответственности и реального контракта.

## Проекционная ответственность

UI-проекция становится юнитом, когда родитель использует её как завершённую область и не определяет её внутреннее устройство.

```text
MainLayout отвечает за размещение Header.
Header отвечает за содержание верхней области.
Navigation отвечает за навигационную проекцию внутри Header.
```

Wrapper, divider, иконка или технически вынесенный фрагмент JSX остаются реализацией ближайшего юнита, пока для них нет отдельной ответственности.

## Поведенческая ответственность

Поведение получает юнит, когда имеет отдельно формулируемый результат, контракт и собственные правила, зависимости, состояние, исходы или область жизни.

```text
Search отвечает за поисковую проекцию и получение результатов.
Upload отвечает за получение готового артефакта.
Session отвечает за состояние пользовательской сессии.
```

## Вложенный юнит

Вложенный юнит используется, когда ответственность является частью результата родителя и прямой доступ к ней нужен только родителю.

```text
main-layout/
├── index.ts
└── ui/
    └── header/
        ├── index.ts
        └── ...
```

Правила связи:

- родитель импортирует ребёнка через его фасет;
- ребёнок не импортирует родителя или предков;
- соседние дети не импортируют друг друга напрямую;
- родитель передаёт детям данные и возможности через их контракты;
- внешний код не импортирует ребёнка напрямую;
- родитель может явно включить возможность ребёнка в собственный API.

Эти ограничения сохраняют направленное дерево владения и не позволяют containment-связям образовывать циклы.

## Подъём юнита

Если прямой доступ к вложенному юниту требуется потребителям за пределами родителя, ответственность поднимается в ближайшую общую область.

```text
До:
main-layout/ui/header/

После появления нескольких потребителей:
compositions/widgets/header/
```

Реэкспорт родителем допустим, когда внешний потребитель по-прежнему использует общий контракт родителя. Если потребителю нужен самостоятельный прямой доступ к ребёнку, требуется подъём, а не цепочка реэкспортов.

## Родитель без собственной ответственности

Юнит не используется как пустой контейнер детей. Если родитель только реэкспортирует набор независимых юнитов и не обеспечивает собственного результата, он является группой либо лишней границей.
