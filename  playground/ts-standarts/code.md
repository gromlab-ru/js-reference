# Как мы пишем код на TypeScript

Здесь согласованы запись литералов объектов и массивов и выбор между стрелкой и `function`. Остальные решения
предложены для итогового ревью. Отступай от принятого правила только там, где его соблюдение не позволяет
выполнить требование задачи. Форму данных описывай по [правилам типов](types.md).

## Переменные и константы

- Выбирай `const`, если самой переменной не нужно присваивать другое значение. `push` меняет массив, но не требует
  `let`. Используй `let` для переназначения, например для счётчика цикла. В новом коде не используй `var`.
- Объявляй переменную рядом с первым использованием. Если значение уже известно, присвой его сразу. Не подставляй
  временные `0`, `''` или `{} as Type`, чтобы заполнить переменную следующей строкой.
- Обычное значение называй в `camelCase`: `flightId`, `retryDelayMs`. Для общего фиксированного лимита, кода
  или значения по умолчанию на уровне модуля используй `SCREAMING_SNAKE_CASE`. Регистр определяет назначение,
  а не слово `const` или `export`. Для набора литералов см. [правило `as const`](types.md#когда-использовать-as-const).
- Покажи в имени, как читать значение: `isBoardingOpen` — признак, `flightIds` — список идентификаторов,
  `flightsById` — коллекция для поиска по идентификатору.

```ts
const MAX_PAGE_SIZE = 50

const getPageOffsets = (total: number) => {
  const offsets: number[] = []
  for (let offset = 0; offset < total; offset += MAX_PAGE_SIZE) {
    offsets.push(offset)
  }
  return offsets
}
```

## Выражения и блоки

- Отступ — два пробела. Если запись продолжается на той же строке, после запятой ставь пробел. Бинарные операторы
  и `=>` отделяй пробелами: `price * count`.
  Пиши `load(id)` и `if (ready) {`. Открывающую `{` оставляй на строке условия или объявления; продолжение блока
  записывай как `} else {`, `} catch (cause) {` или `} finally {`.
- Для обычной строки используй одинарные кавычки, двойные — если так меньше экранирования (`"O'Brien"`).
  Для подстановки или многострочного текста используй обратные кавычки: `` `Рейс ${flightId}` ``.
- Не ставь `;` в конце инструкции. Если следующая строка может продолжить предыдущее выражение, поставь разделитель
  перед ней: `;[first, second] = [second, first]`. В списках свойств, элементов, параметров и аргументов не оставляй
  запятую после последнего.
- Между самостоятельными объявлениями на уровне модуля оставляй одну пустую строку. Внутри функции отделяй ею
  законченный шаг, если это помогает увидеть следующий. Не добавляй пустую строку сразу после `{` или перед `}`.
- Ориентир — 120 символов. Переноси выражение между его частями. В длинной цепочке вызовов начинай каждое
  следующее звено с `.`, а в многострочном условии оставляй `&&` или `||` в конце продолжающейся строки.

## Объекты и массивы

Короткий литерал объекта или массива оставляй на одной строке, если значение легко прочитать целиком.
Правило «каждое поле на своей строке» относится к [объявлению объектного типа](types.md#объектный-тип-и-его-поля).

```ts
const flight = { flightId: 'F42' }

const flightIds = ['F42', 'F73']
```

При переносе пиши по одному свойству объекта или элементу массива на строке. Закрывающую скобку ставь на своей
строке с тем же отступом, что и строка с открывающей скобкой. Короткий вложенный объект можно оставить на одной
строке, как каждый рейс в массиве `departures`.

```ts
const departureBoard = {
  airport: 'Пулково',
  departures: [
    { flightId: 'F42', destination: 'Екатеринбург' },
    { flightId: 'F73', destination: 'Нижний Новгород' },
    { flightId: 'F91', destination: 'Калининград' }
  ]
}
```

Если имя переменной совпадает с ключом, пиши `{ flightId }` вместо `{ flightId: flightId }`. При чтении нескольких
свойств одного объекта удобно извлечь их вместе: `const { flightId, gate } = boardingPass`. Для одного обращения
достаточно `boardingPass.gate`.

Если исходный объект должен сохранить прежние значения, пиши `{ ...boardingPass, gate: 'B2' }`: новое значение
стоит **после** `...`, поэтому заменит старое. Копии `{ ...obj }` и `[...items]` поверхностные: вложенные объекты
остаются общими. Если задача — добавить элемент в ту же очередь, используй `push`; копия изменила бы поведение.

## Функции

### Обычная именованная функция

Используй `const` со стрелкой. Результат одного выражения можно записать сразу после `=>`. Если нужны несколько
действий, оставь стрелку и используй блок; для возврата значения из него напиши `return`.

```ts
const lineTotal = (price: number, count: number) => price * count
```

Для объекта параметров укажи [имя его типа](types.md#тип-объекта-в-параметре-функции).
Если описываешь вызов без реализации, используй [правила записи сигнатур](types.md#сигнатуры-функций-и-методов).

### Параметры и вызовы

- Пиши `() => …` без параметров и `id => …` для одного простого параметра, тип которого уже известен. При явной
  аннотации, деструктуризации или значении по умолчанию скобки нужны: `(id: string) => …`, `(limit = 20) => …`.
  Чтобы вернуть литерал объекта одним выражением, заключи его в скобки: `(flightId: string) => ({ flightId })`.
- У экспортируемой функции укажи тип результата; у локального вычисления оставь вывод типа, если он очевиден.
  Значение по умолчанию задавай в параметре: `limit = 20` сохраняет переданный `0`.
- Короткий вызов оставляй на одной строке. При переносе пиши по одному аргументу на строке и закрывающую `)`
  на уровне начала вызова. В объявлении функции так же переноси параметры, оставляя `)` вместе с типом результата.
- Передавай функцию по имени, когда аргументы, с которыми её вызовут, ей подходят. В `codes.map(parseInt)` индекс
  попадает на место основания системы счисления. Для десятичных кодов пиши `codes.map(code => parseInt(code, 10))`.

```ts
const departureTimeFormat = new Intl.DateTimeFormat(
  'ru-RU',
  {
    timeZone: 'Europe/Moscow',
    hour: '2-digit',
    minute: '2-digit',
    timeZoneName: 'short'
  }
)
```

### Когда использовать `function`

- **Перегрузки.** Запиши несколько сигнатур над одной реализацией. В примере ниже тип результата зависит от аргумента.
- **Генератор.** Если функция выдаёт значения через `yield`, используй `function*` или `async function*`.
- **Обработчик с `this`.** Если обработчику нужен `this`, который задаёт вызывающий код, используй обычную функцию.
  Стрелка берёт `this` из внешней области.
- **Вызов до объявления.** Если вызов должен выполниться до строки объявления функции, используй `function`.
  Стрелку в `const` можно вызвать только после инициализации.
- **Функция утверждения (`asserts`).** У `function` достаточно аннотации `asserts` в сигнатуре. У стрелки для сужения
  типа после вызова нужно явно указать тип самой переменной. Обычному предикату `value is T` достаточно стрелки.

```ts
function normalize(value: string): string
function normalize(value: readonly string[]): string[]
function normalize(value: string | readonly string[]): string | string[] {
  return typeof value === 'string' ? value.trim() : value.map(code => code.trim())
}

normalize(' A ') // string
normalize([' A ']) // string[]
```

## Классы и методы

- Пиши имя класса в `PascalCase`. Сначала объявляй поля, затем конструктор, публичные операции и закрытые
  вспомогательные методы. Если одно поле при инициализации читает другое, учитывай порядок: поля создаются сверху вниз.
- Известное начальное значение указывай у поля. Значение из аргумента задавай в конструкторе. Если поле нельзя
  переназначить после создания, его удобно объявить прямо в параметре: `readonly flightId: string`. Используй
  `static`, если к члену нужно обращаться через класс без экземпляра.
- Для состояния, закрытого и в JavaScript, используй `#count`. `private` ограничивает доступ при проверке TypeScript;
  `protected` открывает член также для наследников. У обычного публичного метода `public` можно опустить.

```ts
class BoardingCounter {
  #count = 0

  constructor(readonly flightId: string) {}

  get count(): number {
    return this.#count
  }

  board(): void {
    this.#count += 1
  }
}
```

Операцию записывай методом: `board() { … }`. Для чтения значения без изменения состояния подходит геттер `get count()`.
Если метод передают отдельно от экземпляра, запись `counter.board` не сохраняет `this`. Для одного места передачи
подойдёт `() => counter.board()`. Если сам обработчик должен сохранять экземпляр при любой передаче, объяви его
стрелочным полем: `onScan = () => this.board()`.

## Условия и обход

- Ставь фигурные скобки у `if`, `else` и циклов даже для одной инструкции. Если при ошибке или отсутствии данных
  продолжать нельзя, выйди через `return` или `throw`. После такой ветки `else` не нужен. Для выбора одного
  из двух коротких значений используй `?:`; при нескольких ветвях с действиями пиши `if` или `switch`.
- Для чтения необязательного поля используй `?.`, для подстановки при `null` или `undefined` — `??`.
  В `options?.limit ?? MAX_PAGE_SIZE` переданный `0` сохранится. `||` уместен, только если нужно заменить
  также `0`, `false` или пустую строку.
- В `switch` пиши `case` и его действия на разных строках. Завершай ветку `return`, `throw` или `break`, если
  не нужен переход дальше. У конечного набора вариантов проверка через `never` обнаружит пропущенную ветку.

```ts
type BoardingStatus = 'scheduled' | 'open' | 'closed'

const getBoardingLabel = (status: BoardingStatus): string => {
  switch (status) {
    case 'scheduled':
      return 'По расписанию'
    case 'open':
      return 'Идёт посадка'
    case 'closed':
      return 'Посадка завершена'
  }

  return status satisfies never
}
```

Выбирай обход по результату: `map` преобразует каждый элемент, `filter` отбирает элементы, `find` возвращает
найденный элемент или `undefined`, `some` отвечает да или нет. Для действий по порядку и досрочного выхода
используй `for (const flight of flights)`: `continue` пропускает элемент, `break` завершает цикл. Если нужен индекс
или шаг, как у `getPageOffsets`, пиши обычный `for`. Если число повторов определяется условием, подойдёт `while`.

## Асинхронный код и ошибки

- Если следующему шагу нужен результат, используй `await`. Для последовательного сохранения пиши `await save(id)`
  внутри `for (const id of ids)`. Если операции независимы и их можно начать вместе, пиши `await Promise.all(ids.map(save))`.
  `forEach(async …)` не ждёт завершения вызовов.
- У `Promise.all` порядок результатов совпадает с порядком переданных операций. При отказе общий промис отклоняется,
  а уже начатые операции не отменяются. Если нужен исход каждой операции, используй `Promise.allSettled`.
- Верни промис вызывающему коду, дождись его или обработай отказ фоновой операции: `void save().catch(reportFailure)`.
  Одна запись `void save()` отказ не обрабатывает.
- В `try` помещай операции, ошибки которых обрабатывает этот `catch`. Чтобы перехватить отказ внутри функции,
  дождись промиса в `try`. При записи `return load()` асинхронный отказ получит вызывающий код, минуя этот `catch`.

```ts
const loadBoard = async (load: () => Promise<string[]>): Promise<string[]> => {
  try {
    return await load()
  } catch (cause) {
    throw new Error('Не удалось загрузить табло вылетов', { cause })
  }
}
```

Выбрасывай `Error`. Если добавляешь пояснение, сохрани исходную причину в `cause`. В `catch` значение не обязательно
является `Error`: прежде чем читать `message`, проверь `cause instanceof Error`. Освобождение захваченного ресурса
помещай в `finally`, чтобы оно выполнилось и при успехе, и при ошибке. Не возвращай значение из `finally`:
оно заменит результат или скроет исходное исключение.

## Модули

- Статические импорты пиши в начале файла единым блоком. Обычный порядок: встроенные модули, внешние пакеты,
  алиасы проекта, относительные пути. Импорт с побочным эффектом, например `import './register.js'`, размещай
  с учётом порядка инициализации. Не переставляй его ради сортировки: от регистрации может зависеть другой модуль.
- Если нужны только типы, пиши `import type`. Если из того же модуля нужно и значение, пометь `type` у конкретного
  имени. Класс, который создают через `new`, нужен как значение.
- Для собственного кода используй именованные экспорты. `export default` оставляй для случаев, когда этого требует
  потребитель. При реэкспорте перечисляй нужные имена; `export *` подходит, только если намеренно открываешь
  и будущие именованные экспорты модуля.

Пример для ES-модулей Node.js. В `flight.ts` объявлены тип и операция:

```ts
export type Flight = {
  flightId: string
}

export const getFlightLabel = (flight: Flight): string => `Рейс ${flight.flightId}`
```

В `board.ts` операция нужна во время выполнения, а `Flight` — только для типов:

```ts
import { getFlightLabel, type Flight } from './flight.js'

export const getBoardLabels = (flights: readonly Flight[]): string[] => flights.map(getFlightLabel)

export { getFlightLabel }
export type { Flight }
```

## Проверка

- Для форматтера сравни короткую и многострочную запись: пробелы, скобки, переносы аргументов, полей и элементов.
- Для линтера возьми два разных случая: `let` без переназначения и `let` у счётчика цикла. Замечание нужно в первом.
- При ревью выясни, что изменится для вызывающего кода: сохранится ли переданный `0`, кто увидит изменение исходного
  объекта, какой `this` получит обработчик и кто обработает отказ промиса. Для `function` назови свойство объявления,
  которое требуется именно здесь.
