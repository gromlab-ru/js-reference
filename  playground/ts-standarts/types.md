# Как мы пишем типы в TypeScript

Здесь собраны принятые правила написания типов в TypeScript. Применяй их при разработке и ревью.
Отступай от конкретного правила только там, где его соблюдение не позволяет выполнить требование задачи.

## Как оформлять объявления

- **Имена.** Типы, интерфейсы, перечисления и члены `enum` называй в `PascalCase`, собственные поля и методы —
  в `camelCase`. Не добавляй `I`, `T` или `Enum` к имени объявления только для обозначения его вида.
- **Отступ и пробелы.** Используй два пробела на уровень. Пиши `limit: number`, `cursor?: string`, `Page<T>`.
  Отделяй пробелами `=`, `|`, `&` и `=>`. Не выравнивай знаки у соседних строк.
- **Блок.** Открывающую `{` ставь на строке объявления, закрывающую `}` — на своей строке на уровне объявления.
  Внутри пиши по одному полю, методу или члену `enum` на строке. У полей и методов не ставь `;` или `,`;
  у `enum` ставь запятую *между* членами. В конце объявления точка с запятой не нужна.
- **Пустая строка.** Между самостоятельными объявлениями оставляй одну пустую строку. Соседние члены одного блока
  и перегрузки одного метода пиши подряд. Не добавляй пустые строки сразу после `{` и перед `}`.
- **Перенос.** Ориентир — 120 символов. В длинном объединении или пересечении оставь `=` на строке объявления.
  Каждую часть пиши с новой строки, начиная с `|` или `&`. В длинной сигнатуре переноси по одному параметру на строку;
  закрывающую `)` оставляй вместе с результатом: `) => Result` или `): Result`.

## Конструкции TypeScript

### Объектный тип и его поля

Для обычного объекта пиши поля прямо в объявлении `type`. Если тип описывает рейс, достаточно имени `Flight`,
даже когда в нём только `flightId`. Суффикс `Ref` уместен, когда нужно отличить ссылку на рейс от самого рейса.

```ts
type Flight = {
  flightId: string
}
```

Ставь `?` у имени поля, если ключ можно пропустить: `cursor?: string`.
Запись `cursor: string | undefined` требует сам ключ. Если полю нельзя присвоить новое значение через этот тип,
добавь `readonly` перед именем: `readonly id: string`.

#### Тип объекта в параметре функции

Используй существующий тип или объяви новый рядом с функцией. В параметрах можно извлечь поля, но не объявляй их
типы там же: `{ offset, limit }: PageParams` читается без повтора имён. Для простого параметра достаточно `limit: number`.

```ts
type PageParams = {
  offset: number
  limit: number
}

const page = (ids: readonly string[], { offset, limit }: PageParams) =>
  ids.slice(offset, offset + limit)
```

### Интерфейсы

Выбирай `interface`, когда другое объявление должно дополнять тот же интерфейс. Например, так библиотека позволяет
добавлять события в `DeliveryEvents`. Если нужен *новый* интерфейс на основе существующего, используй `extends`:
его поля не попадут в исходный интерфейс.

```ts
interface DeliveryEvents {
  sent: Date
}

interface PickupEvents extends DeliveryEvents {
  collected: Date
}
```

### Литералы

Когда важны сами допустимые значения, перечисляй их прямо. Отдельные типы для `'queued'` и `'sent'` не нужны.

```ts
type DeliveryStatus = 'queued' | 'sent'

type DeliveryEvent =
  | 'shipment.accepted_by_carrier'
  | 'shipment.arrived_at_sorting_center'
  | 'shipment.received_by_recipient'
```

#### Когда использовать `as const`

Добавляй `as const` к литералу объекта или массива, когда для дальнейшего кода важны точное значение поля
или длина и типы позиций кортежа. Например, из списка классов обслуживания можно получить тип допустимых значений:

```ts
const CABIN_CLASSES = ['economy', 'business'] as const

type CabinClass = (typeof CABIN_CLASSES)[number]
```

Без `as const` список имеет тип `string[]`, а `CabinClass` допускает любую строку. С `as const` получается кортеж
`readonly ['economy', 'business']`, и `CabinClass` допускает только `'economy'` и `'business'`.

Если в объекте важна только метка, достаточно `kind: 'accepted' as const` у этого поля. У отдельной константы
`const status = 'accepted'` тип уже `'accepted'`. Для функции, которая только читает список рейсов, достаточно
параметра `readonly Flight[]`. Сам объект в JavaScript `as const` не замораживает.

### Объединения и пересечения

**Для объектных частей `|` и `&` используй имена типов или интерфейсов.** Вместо `Flight | { parcelId: string }` объяви `Parcel`,
даже если у него одно поле и он понадобится лишь один раз. Уже объявленный `Flight` используй как есть.

```ts
type Parcel = {
  parcelId: string
}

type SearchResult = Flight | Parcel

type PlannedLoad = Parcel & Flight
```

Поиск может вернуть рейс или посылку. Для назначения посылки на рейс нужны поля обоих типов.
Если у вариантов уже есть общее поле `kind`, укажи его конкретное значение в каждом типе, например `kind: 'accepted'`.
Так проверка `kind` сужает тип до нужного варианта. В `Flight | null` значение `null` остаётся на месте.

### Перечисления

Выбирай `enum`, когда в коде нужны именованные значения, например `DeliveryMethod.Pickup`. Если значение передаётся
во внешнем формате, задай его явно: перестановка членов не должна менять отправляемый код.

```ts
enum DeliveryMethod {
  Pickup = 'P',
  Courier = 'C'
}
```

### Массивы

Для обычного массива пиши `T[]`, если элемент — примитив или именованный тип: `string[]`, `Flight[]`, `SearchResult[]`.
У пустого массива, который предстоит заполнить, укажи тип явно. Если начальные значения уже дают нужный тип,
аннотацию можно опустить: у `const cities = ['Тула', 'Омск']` выведется `string[]`.

```ts
const flights: Flight[] = []
flights.push({ flightId: 'F42' })

const externalIds: Array<string | number> = ['F42', 42]
```

- Если перечисляешь типы элементов прямо в объявлении, используй `Array<string | number>`. В таком массиве можно
  смешивать строки и числа. Запись `string[] | number[]` означает другое: либо массив строк, либо массив чисел.
- Если функция только читает список, принимай `readonly Flight[]` или `ReadonlyArray<string | number>`. Через такую
  ссылку нельзя заменить элемент или вызвать `push`. Сам по себе `const` этого не запрещает, как видно у `flights`.

### Кортежи и словари

- Если у позиций разный смысл, используй кортеж с подписями: `readonly [start: number, end: number]`.
- Для всех ключей конечного набора пиши `Record<DeliveryMethod, string>`. Если часть ключей может отсутствовать,
  используй `Partial<Record<DeliveryMethod, string>>`. Для произвольных ключей подходит индексная сигнатура:
  `[parcelId: string]: Date | undefined`, если записи может не быть.

### Обобщения

Укажи параметр типа после имени, если он выбирается для всей структуры. Если он выбирается заново при каждом
вызове, ставь его перед `(`. Ограничение записывай через `extends`, тип по умолчанию — через `=`.

```ts
type Page<TItem, TCursor = string> = {
  items: readonly TItem[]
  nextCursor?: TCursor
}

type ReadField = <T, K extends keyof T>(value: T, key: K) => T[K]
```

### Производные типы

- Тип существующего значения получай через `typeof`, например `typeof page`. Для имён полей используй `keyof PageParams`,
  для типа конкретного поля — `PageParams['limit']`.
- Выбирай поля через `Pick<PageParams, 'limit'>`, исключай — через `Omit`. `Partial<T>` делает поля необязательными,
  `Readonly<T>` запрещает их переназначать. Если нужно своё преобразование полей, используй запись `[K in keyof T]`.
- Когда результат зависит от исходного типа, пиши условный тип `T extends U ? X : Y`. Чтобы извлечь часть типа,
  используй `infer`: `type ItemOf<T> = T extends ReadonlyArray<infer Item> ? Item : never`.

### Сигнатуры функций и методов

В типе функции перед результатом ставь `=>`. В `type` или `interface` операцию объекта записывай методом
с `:` перед результатом. Если функцию передают как обработчик, объяви свойство с типом функции.

```ts
type StatusHandler = (status: DeliveryStatus) => void

type DeliveryTracker = {
  getStatus(id: string): Promise<DeliveryStatus>
  getStatus(ids: readonly string[]): Promise<DeliveryStatus[]>
  onStatusChange?: StatusHandler
}
```

- Сигнатуры одного метода пиши подряд, если тип результата зависит от аргумента. Здесь вызов с одним `id`
  возвращает промис одного статуса, со списком — промис массива.
- `onStatusChange?` означает, что обработчик можно не передать. Если он есть, `status` обязателен. При `strictFunctionTypes`
  свойству нельзя назначить обработчик только для `'sent'`: он должен принимать и `'queued'`. У метода проверка мягче.
- Необязательный параметр записывай как `limit?: number`, остальные аргументы — как `...ids: string[]`.
  Значение по умолчанию задавай в реализации.
- Если тип входа неизвестен, используй `unknown`. Если вызывающий код не использует результат, пиши `void`;
  если вызов не может завершиться обычным возвратом — `never`.

## Проверка

При настройке форматтера сверяй с примерами пробелы, отступы и переносы. При настройке линтера проверь обе формы:
безымянный объект внутри `|` или `&` должен давать замечание даже после переноса строк, а объединение литералов —
проходить. На ревью прочитай итоговое объявление: понятно ли по именам, каких данных достаточно для `|` и какие
нужны вместе для `&`?
