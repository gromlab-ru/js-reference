# Ручная проверка TypeScript с Biome

Открой `./ playground/ts-standarts/` **как корневую папку проекта**. Для сравнения нужны ровно два файла:
[с замечаниями](examples/problems.ts) и [исправленный](examples/correct.ts). Открой их рядом: номера разделов
и имена функций совпадают. Оба файла корректны для TypeScript; различия показывает линтер.

## Быстрый старт

Нужен Node.js 22 или новее. В терминале открытого плейграунда выполни:

```sh
npm ci
npm run lint:problems
npm run check:correct
```

Первая проверка намеренно завершается с кодом `1`: в `problems.ts` есть ошибки. Вторая завершается с кодом `0`:
`correct.ts` проходит линт и форматирование без замечаний. Команды не изменяют примеры.

Для подсветки в VS Code или Cursor включи расширение `biomejs.biome`, после установки зависимостей перезагрузи
окно. В `problems.ts` наведи курсор на `ids.length > 0` внутри `hasFlights`: должно появиться
`[TS-EXTRAS/is-non-empty]`. В `correct.ts` на том же месте стоит `isNonEmpty(ids)`.
Если в терминале замечание есть, а в редакторе нет, проверь в журнале Biome выбранный каталог и версию CLI:
должны использоваться [конфиг этого проекта](biome.json) и локальный Biome `2.6.9`.

## Что сравнить

| Раздел в обоих файлах | Что видно в редакторе |
| --- | --- |
| 1. Массив | `=== 0`, `> 0`, `>= 2` дают три разных подсказки. `countFlights` возвращает саму длину и проходит в обоих файлах. |
| 2. Измерения | `isPresent` и `isDefined` оба сохраняют нулевую задержку, но только второй оставляет `null`. |
| 3. Число | `Number.isInteger(value)` даёт предупреждение, именованный импорт `isInteger` — нет. |
| 4. Типы | Подсвечены безымянные объекты внутри объединения и `ReadonlyArray<Destination>`. Справа — именованные варианты и `readonly Destination[]`. |
| 5. Переменная | Встроенное правило `lint/style/useConst` указывает на `let`, которому ничего не присваивают повторно. |
| 6. Исключение | `[TS-EXTRAS/assert-error]` — информация для ревью. В исправленном варианте оставлена та же проверка `instanceof` и пояснено, почему здесь подавлена подсказка. |
| 7. Ранние возвраты | `lint/style/noUselessElse` отмечает `else` после `return`. Справа отмена и отсутствие данных обработаны до выбора подписи. Сравни оба варианта на `(true, null)` и `(false, 0)`. |

Чтобы проверить исключение вручную, удали строку `// biome-ignore …` в `correct.ts`: подсказка `assert-error`
вернётся. Верни комментарий — она исчезнет. Чтобы отключить **один конкретный код** во всём приложении, см.
[настройку `disabledRules`](../../skills/ts-standarts/assets/biome/README.md#как-отключить-замечание).

Дополнительно: `npm run lint` проверяет оба примера, `npm run lint -- examples/correct.ts` — выбранный файл,
`npm run typecheck` — типы в обоих файлах. Из корня репозитория перейти сюда можно командой `cd './ playground/ts-standarts'`.
Набор `ts-extras-cases/` предназначен для [автоматического сравнения линтеров](ts-extras-biome.md); в ручную проверку он не входит.
