# Проверка переноса правил ts-extras

Проверки входят в рабочий профиль `ts-standarts`. [Результат по каждому правилу](../../skills/ts-standarts/assets/biome/ts-extras.md)
уточняет, где диагностики совпадают, а где нужны сведения о типах из других файлов. `biome migrate eslint`
не перенёс ни одного из 46 исходных правил автоматически; здесь проверяется реализация для Biome.

1. Из корня репозитория запусти `npm ci` и `npm run test:ts-biome`. Тест создаёт проект потребителя с поставляемым
   конфигом. В [positive.ts](ts-extras-cases/positive.ts) ожидаемое имя указано на той же строке, что и выражение.
   На [negative.ts](ts-extras-cases/negative.ts) не должно быть ни одного сообщения `TS-EXTRAS`.
2. Чтобы воспроизвести сравнение с исходным плагином, установи эталон во временный каталог и укажи его скрипту:

```sh
REF=$(mktemp -d)
npm install --prefix "$REF" --no-save --ignore-scripts eslint@10.15.0 eslint-plugin-typefest@1.7.1 typescript@6.0.3 ts-extras@3.0.0 type-fest@5.10.0
npm run test:ts-upstream -- "$REF"
```

[Скрипт](compare-upstream.mjs) проверяет примеры компилятором, включает все исходные правила `prefer-ts-extras-*`
и сравнивает их имена и строки с теми же метками. Замечания ESLint на отрицательных примерах выводятся отдельно:
например, для импортированного `Ids` у ESLint есть тип получателя, а у плагина Biome — только имя импорта.
Для запуска самих правил и регулярных проверок CI эталонная установка не нужна.
