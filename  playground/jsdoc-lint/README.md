# Проверка JSDoc с Biome

**`npm run lint`** проверяет все файлы в [`examples/`](examples/) по [правилам скилла](../../skills/jsdoc-standarts/SKILL.md).
Запускай в терминале открытого плейграунда. Из корня репозитория сначала выполни `cd './ playground/jsdoc-lint'`.

```sh
npm ci
npm run lint
```

Чтобы увидеть ошибки только в одном файле:

```sh
npm run lint -- examples/documented.ts
```

В примерах намеренно есть нарушения. Например, однострочный JSDoc над `RequestSource` в `documented.ts` даёт
`[JSDOC-BLOCK]`. При ошибках команда завершается с кодом `1`, без ошибок — с `0`. Файлы она не меняет.

## Подсветка в редакторе

Открой `jsdoc-lint` как корневую папку и включи интеграцию Biome (для VS Code и Cursor — расширение `biomejs.biome`).
После `npm ci` перезагрузи окно редактора. Терминал и редактор должны использовать [один конфиг](biome.json)
и **локальную** сборку Biome. `npm ci` устанавливает сборку `426c33d` с поддержкой плагина; задавать `BIOME_BINARY` вручную не нужно.

Для проверки открой [`examples/prose.ts`](examples/prose.ts): над `takeNextAfterRename` написано `ids` вместо `queue`.
Ожидаемое замечание — `[JSDOC-ARGS]`. Если оно есть в терминале, но отсутствует в редакторе, посмотри в журнале Biome,
какой исполняемый файл и какой корень проекта выбрало расширение.
